# Design — Actual production UI and judge proof direction

## Product reality and story

- **Actual user:** agent builder / independent operator seeking on-demand external research data.
- **Job:** ask a task -> discover capability -> inspect real 402 price -> authorize fixed token cap -> obtain outside result -> verify payment.
- **Primary moment:** a real 18-post social research result next to the exact 0.005 USDC Celo transfer and agent ID10059.
- **States:** unauthed operator login, loading catalog, quote awaiting approval, halted by policy, delivered paid/free result, uncertain settlement/read-only reconciliation, saved ledger/revisit, public recorded proof.

## Art direction (product-specific, not a generic SaaS template)

Treat **a payment receipt as an instrument reading**, not as a victory badge: only real prices/tx links earn prominent typographic weight; the data itself is the focal point, not the code. The open judge route uses a restrained editorial split: large research/purchase statement, measured receipt panel, four transaction beats, then actual purchased source material. The operator UI remains compact like a research desk, not a marketing page.

## Three retrospective territories (concept comparison, not fabricated earlier design exploration)

1. **Audit Ledger:** dense data panels, chain IDs/amounts, high credibility but can bury actual human value. Implemented in original operator workspace.
2. **Paid Result Editorial:** strongly framed question/receipt metrics followed by real source cards; high comprehension and sponsor proof. Selected for public recorded `/proof` route.
3. **Network Map:** service discovery illustrated as graph of providers and money routes; memorable but requires invented topology/extra assets and distracts from verified task. Rejected.

The distinction is composition and story, not only colors. This retrospective design explanation is not an approved original design lock.

## Motion and assets

- Icon/wordmark motif is SVG. Source imagery is real browser captures, not generated stock photos.
- Motion restricted to small state feedback, hover/focus and scroll; no fake payment animation or artificial time-delays.
- No heavy motion storyboard needed for critical task; if a final demo adds motion, record each exact source/state first.
- Responsive: proof stacks hero/receipt on small screens; post text wraps; keyboard-focus outlines on source and expansion buttons.

## Visual QA verdict

Local proof desktop/mobile composition inspected, readably branded with checked-receipt mark. **PARTIAL PASS** for real screenshots, but full DESIGN_LOCK remains OPEN because no formal external reference board or user-approved distinctive name, and no recorded final presentation video. A missing public deployment is a delivery constraint, not a compositional defect.
